# Выпуск SDK 2.0.3

Версии пакета, нативных зависимостей и runtime metadata должны совпадать.
Инструкции установки и настройки приложения находятся в README.md;
изменения интеграции звонков — в docs/MIGRATION_2.md.

1. Выполните полный набор нативных тестов и проверьте оба podspec: PushPlatformSDK и PushPlatformExtension версии 2.0.3.
2. Зафиксируйте проверенные исходники и создайте git-тег `v2.0.3` на этом коммите.
3. Swift Package Manager и CocoaPods должны разрешать оба продукта из одного тега.
4. Workflow `ios-sdk-release` запускается вручную; публикация CocoaPods управляется его параметром `publish`.

## Обязательные условия выпуска

1. Сохраните прежние локальные правки отдельными коммитами в отправленных ветках; синхронизируйте основные каталоги с main.
2. Подготовьте версии, lockfile, runtime metadata, документацию и генерируемые файлы до финального коммита. Отправьте все коммиты выпуска.
3. Дождитесь успешного CI PR, затем успешного CI main после merge.
4. Создайте новый тег vVERSION на проверенном коммите. Существующие опубликованные теги не перезаписывайте.
5. Дождитесь успешных проверок тега. До этого GitHub Release не публикуется.
6. Опубликуйте стабильный GitHub Release и проверьте последующие workflow, если они запускаются публикацией.
7. Проверьте все затронутые основные каталоги и worktree: `git status --porcelain --untracked-files=all` должен быть пуст, все коммиты должны быть доступны в origin.

Красная или незавершённая обязательная проверка блокирует публикацию. Наличие незакоммиченных файлов блокирует публикацию и завершение работы. Публикация пакетов в реестры выполняется отдельной штатной процедурой; GitHub Release сам по себе её не запускает.
